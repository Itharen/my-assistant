"For my agentic systems, I do not need “one RAG.”"
"I need different retrieval layers for different kinds of knowledge:"
" project memory, development rules, requirements, documentation, tool usage, architectural patterns, and implementation history."
"Those are not the same problem."
"A rule system should not behave like a documentation search."
" A requirement trace should not behave like a generic knowledge base."
" Tool context should not be loaded the same way as project history."
"So the direction is becoming clear:"
"RAG has to become a microservice architecture inside Dynamo."
"Not one retrieval box."
" A set of specialized context services that agents can use depending on the task."
"That is where RAG starts becoming real infrastructure.
